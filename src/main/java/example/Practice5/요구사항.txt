[문제 요구사항] JPA 실습 :  게시판 및 댓글 CRUD 관리

[조건 1] 엔티티 설계 : "게시판(BoardEntity)", "댓글(CommentEntity)" 엔티티를 생성한다.
-엔티티의 주요 역할과 관계를 명확히 구분할 것.
-JPA 어노테이션(@Entity, @Table, @Id, @GeneratedValue, @Column, @OneToMany, @ManyToOne, @JoinColumn 등)을 활용한다.
-BaseTime을 상속받아 createdAt, updatedAt 자동 기록 기능을 포함한다.
-BoardEntity : 게시글 식별번호(id, PK), 작성자(author), 비밀번호(password), 내용(content)
-CommentEntity : 댓글 식별번호(id, PK), 작성자(author), 비밀번호(password), 내용(content), 게시글(boardEntity, FK)
-연관관계 : Board(1) ↔ Comment(N) 양방향/단방향 참조 구조 설계
-한 게시글에는 여러 댓글 등록 가능 (@OneToMany(mappedBy = "boardEntity", cascade = CascadeType.ALL))
-각 댓글은 특정 게시글에 소속 (@ManyToOne, @JoinColumn(name = "board_id"))

[조건 2] BaseTime 설계 : 모든 엔티티의 생성일·수정일을 자동으로 기록하기 위한 상속 전용 클래스이다.
-@MappedSuperclass : 엔티티 상속 전용 클래스 지정
-@EntityListeners(AuditingEntityListener.class) : JPA 감사(Auditing) 기능 활성화
-@CreatedDate, @LastModifiedDate : insert / update 시 자동 시간 기록 (createdAt, updatedAt)
-스프링 부트 메인 실행 클래스(AppStart)에 @EnableJpaAuditing 어노테이션 추가
-각 엔티티에서 extends BaseTime으로 상속받아 공통 필드 사용

[조건 3] Controller 및 Service 기능 구현 (REST API)
-게시글 등록 기능 : POST /api/board
요청 본문(@RequestBody BoardDto)으로 작성자, 비밀번호, 내용을 전달받아 저장한다.
-게시글 목록 조회 기능 : GET /api/board
전체 게시글 목록을 반환한다.
각 게시글 정보에는 작성일시(createdAt)와 해당 게시글에 달린 **댓글 목록(comments)**이 함께 포함되어야 한다.
-게시글 삭제 기능 : DELETE /api/board?id={id}&password={password}
쿼리 스트링(@RequestParam)으로 게시글 번호와 비밀번호를 전달받아 일치 여부 확인 후 삭제한다.
게시글 삭제 시 연결된 댓글도 함께 삭제(Cascade) 처리한다.
-댓글 등록 기능 : POST /api/board/comments
요청 본문(@RequestBody CommentDto)으로 대상 게시글 번호(boardId), 작성자, 비밀번호, 내용을 전달받아 해당 게시글의 댓글로 등록한다.
-댓글 삭제 기능 : DELETE /api/board/comments?commentId={commentId}&password={password}
쿼리 스트링(@RequestParam)으로 댓글 번호와 비밀번호를 전달받아 일치 여부 확인 후 삭제한다.
